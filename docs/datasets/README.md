## Summary of the dataset note

No single public dataset covers all four incident types with compatible sensor readings, so the
note recommends combining specialised sources:

| Domain | Dataset / resource named in the note | What it provides (per the note) |
|---|---|---|
| Traffic accidents and jams | FARS and UTD19 (NHTSA mentioned) | Crash references, traffic flow, speed and occupancy |
| Fires | "Fire and Smoke Digital Twin data" | Historical fire incidents and related fire data |
| Flooding | NYC FloodNet (GitHub, NYC Open Data) | Water depth, event duration and time-series measurements |
| Power-grid anomalies | SmartGrid-CyberPhysical-Attack-Dataset (IEEE DataPort) | Power-grid behaviour and cyber-physical attack scenarios |

The datasets differ in schema, location, sampling rate and labels, so they must be normalised
into one common incident-reference format.

The note's key recommendation is that the library should hold more than genuine incidents:

- **real incident references:** documented fires, floods, accidents and congestion;
- **normal situations:** rush-hour congestion, ordinary water-level changes, normal air-quality fluctuations;
- **sensor faults:** frozen readings, spikes, drift, dropped values, replayed messages;
- **ambiguous situations:** smoke without a confirmed fire, congestion without a crash, high water that does not persist;
- **cross-domain incidents:** for example a flood that also disrupts traffic.

This lets the City Brain compare competing explanations instead of picking the nearest
incident reference; Guardian must still validate sensor trust on its own. The note recommends a
unified reference library from real datasets **plus synthetic scenarios generated by the Twin**,
evaluated on scenarios that were not used to build it.

## Who uses it

- **Graph team** (detection thresholds, baselines, reference cases): main user.
- **LLM module**: possible later use as benchmark cases and short examples in the prompt (the
  prompt limit is 1,500 characters, so at most one or two retrieved cases).
- **Mock**: realistic baselines and incident shapes for scenario files.
