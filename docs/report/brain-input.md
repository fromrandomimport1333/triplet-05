# City Brain: input module (report paragraph)

**What.** The input module is the front door of the City Brain. It is the only part of the Brain that reads the Twin and Guardian topics. Nothing reaches detection, scoring or the output stage unless it is genuine, fresh, well-formed and consistent with the city description.

**How.** Each message runs through seven checks in a fixed order, stopping at the first failure. The checks are envelope, HMAC-SHA256 signature over the exact body text, a ±10 s timestamp window, a 60 s replay memory (plus increasing `seq` per device when present), pydantic format validation, IDs declared in `twin/meta`, and each sensor's `min`/`max` range. Accepted messages are turned into plain internal messages on `brain/internal/…`. City description, trust verdicts, quarantines and layer status are retained there, so a restarted module gets the full state back at once. Rejected messages are logged as JSON lines and reported on `brain/error` with a shared error code. The module also tracks whether the Twin and Guardian are online, from their Last Will status topics and from Guardian's silence (no verdict for 30 s), which lets the Brain switch to safe mode.

**Why.** TLS protects only the link to the broker. The HMAC proves end to end that a holder of the pair key wrote the message and that it was not changed in the broker. The timestamp and id checks stop captured messages from being replayed. The ID and range checks stop impossible data before it can trigger an action. Topic names, field-name mappings, time windows and keys all live in configuration files, so the module adapts to the other layers without code changes.

**Limits.** A sensor that sends plausible but false values with a valid HMAC passes these checks. Detecting it is Guardian's job, and the Brain relies on its verdicts. Retained and status messages skip the freshness and replay checks, because the broker delivers them again by design, but they still need a valid signature. With a shared HMAC key, any holder of the key can sign. Ed25519 for Guardian, already supported, removes that weakness for verdicts. Measured cost is under 0.1 ms per message, far below the 5 ms budget.
