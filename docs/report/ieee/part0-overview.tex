\section{Part 0: Triplet Overview and Integration}
\subsection{The problem and the idea}
A smart city that reacts automatically to floods, fires and accidents has a new weakness: one broken or hacked
sensor can open the wrong valve or close the wrong road. The challenge asks each triplet of teams to build three
layers that together answer three questions: \emph{What is happening?} (the Twin), \emph{Is this data telling the truth?}
(the Guardian) and \emph{What should we do?} (the City Brain). The idea of our triplet is that no action leaves the
system on data nobody has checked: the Twin produces readings and calls, the Guardian gives every reading a trust
verdict, the Brain weighs each source by that trust and acts only through signed, acknowledged commands. The three layers
are separate programs that share one message bus, so each team builds and tests its layer alone and a partner is a
configuration, not code.

\subsection{How the layers communicate}
\emph{Protocol.} MQTT~3.1.1~\cite{mqtt} over TLS on port 8883, with a certificate signed by a triplet CA and no plaintext
listener. Each layer has its own account (\code{twin}, \code{guardian}, \code{brain}); the Brain's broker configuration lets the Twin
write only \code{city/\#} and \code{twin/\#}, and the Guardian only \code{guardian/\#}.
\emph{Authentication.} Every payload is an envelope \code{\{"v":1,"body":"<JSON text>","hmac"|"hmacs":\{...\}\}}. The tag is
HMAC-SHA256~\cite{hmac} over the exact UTF-8 text of \code{body}, with one key per pair of layers (\code{twin-brain},
\code{twin-guardian}, \code{guardian-brain}); a message read by two layers carries one tag for each. Every body has an \code{id}, a UTC
\code{timestamp} with milliseconds, a \code{source} and, along a chain, a \code{correlation\_id}. Receivers accept a timestamp within
$\pm10$~s, remember an \code{id} for 60~s and require \code{seq} to increase per sensor. Retained messages carry the city description,
verdicts, quarantines and each layer's status, and every layer sets a last-will \code{offline} status.

An envelope looks like this (the body is a JSON \emph{text}, signed exactly as sent; tags shortened):

{\footnotesize\begin{verbatim}
{"v":1,
 "body":"{\"id\":\"tw1-water-07-126\",
   \"timestamp\":\"2026-11-08T22:35:18.267Z\",
   \"source\":\"twin\",\"sensor_id\":\"water-07\",
   \"zone_id\":\"zone-a\",\"type\":\"water_level\",
   \"value\":0.407,\"unit\":\"m\",\"seq\":126}",
 "hmacs":{"brain":"503688..","guardian":"c1a9f0.."}}
\end{verbatim}}

A refused message is never dropped silently: the Brain reports it on \code{brain/error} with a code (wrong key, stale clock,
repeated identifier, bad format, unknown device, value out of range), and the Twin logs why it refused a command.

In this profile the Twin has no inbound REST interface for the other layers. Its REST API (port 8000) exists for tests only and uses separate
keys for the Brain, the Guardian and the test scripts. The Brain's MCP server is a read-only math toolbox with no actuator tool, and
the Guardian's profile uses MQTT alone, so no layer talks MCP to another.

In the attack variant a script makes the Twin publish a validly signed 4.2~m reading on the same sensor. The Guardian stand-in
rejected it (\code{implausible\_jump}, score 0.05), quarantined \code{water-07}, and the Brain opened no incident and sent no command.
The ack took about one second, the time of the Twin's next simulation step.

\subsection{When a layer fails}
Each layer publishes a retained status with a last will, so a partner's failure is visible within seconds and every layer has a
defined degraded behaviour (Table~\ref{tab:degraded}); the Brain's own scenarios B4, B12 and B13 exercise the first rows.

Four points remain. (i) The Twin applies a quarantine notice, but the Twin account is not yet allowed to read
\code{guardian/quarantine/\#} and the notice is sealed for the Brain only. (ii) The Twin--Guardian key has to be agreed and the
real Guardian run against the Twin. (iii) The Brain's scenarios use mock-city ids and a \code{twin/control} message that the Twin does not
implement. (iv) The Brain has no playbook for road closure or public alerts, and no \code{rescue} unit exists in the Twin.
