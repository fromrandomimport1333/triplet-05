# Build

Exact, copy-pasteable steps, verified on the machine this project was built
on. Versions below are what was actually tested, not a guess at minimums.

## Toolchain this was built and tested with

| tool | version tested | minimum expected to work |
|---|---|---|
| CMake | 4.4.3 | 3.16+ |
| GCC | 16.2.1 | any C99-capable GCC |
| Clang | 22.1.8 | any C99-capable Clang |
| Ninja | 1.13.2 | optional — Make works too |
| Python | 3.14.7 | 3.9+ |
| cffi | 2.1.1 | 1.15+ |
| mcp SDK | 2.3.0 | 1.2+ (see note below) |
| pytest | 9.1.1 | 7+ |
| hypothesis | 6.168.5 | 6+ |

**Note on the `mcp` package:** this project was built against `mcp` 2.3.0, in
which the SDK's `FastMCP` class was renamed to `MCPServer`
(`mcp.server.mcpserver`). `mcp_server/server.py` imports `MCPServer` and
falls back to the old `mcp.server.fastmcp.FastMCP` name if that import fails,
so either SDK major version works without edits.

Required system packages: a C99 compiler, CMake, and (for the Python
bindings) Python headers are not needed — `cffi` out-of-line mode compiles
against the already-built static library, not against the Python C API in a
way that needs extra system headers beyond a normal Python dev environment.

## 1. Build the C library and run its tests

Source lives in `brain/src`, tests in `brain/tests`. Run these from `brain/`:

```bash
cmake -S src -B src/build -DCMAKE_BUILD_TYPE=Release
cmake --build src/build
ctest --test-dir src/build --output-on-failure
```

This produces, under `src/build/`:
- `libcitybrain.so` (shared) and `libcitybrain.a` (static)
- one test executable per suite under `src/build/tests/`
- `src/build/bench/cb_bench`, the benchmark driver

Warnings are treated as errors (`CITYBRAIN_WERROR=ON` by default); a build
that produces any compiler warning fails outright.

To also run the longer property-based sweep (50000 cases per property
instead of the default 10000, disabled by default so the fast suite stays
fast):

```bash
ctest --test-dir src/build -R test_property_long -C "" --output-on-failure -VV
# or directly:
./src/build/tests/test_property 50000
```

To run the benchmark:

```bash
./src/build/bench/cb_bench
```

## 2. Install the library (optional, for `find_package()` consumers)

```bash
cmake --install src/build --prefix /usr/local
```

This installs the headers, both library forms, a CMake package-config file
(`citybrain-config.cmake`) under `<prefix>/lib/cmake/citybrain`, and a
`citybrain.pc` pkg-config file. Another CMake project can then do:

```cmake
find_package(citybrain REQUIRED)
target_link_libraries(your_target PRIVATE citybrain::citybrain)
```

## 3. Build and install the Python bindings

**One command, from a clean checkout, with nothing pre-built:**

```bash
pip install -e src/bindings/python
```
(run from `brain/`)

This single command:
1. Reads `src/bindings/python/pyproject.toml` / `setup.py`.
2. Runs `src/bindings/python/build_citybrain.py`, which:
   - configures and builds the C core as a static library via CMake,
     cached under `src/bindings/python/_vendor_build/` (skipped if that
     build already exists — the second `pip install -e` is fast),
   - compiles the `cffi` extension against that static library and the
     real public headers.
3. Installs the `citybrain` Python package in editable mode.

No manual `cmake` invocation, no environment variable, no path edit is
required. This was verified by creating a fresh virtualenv and running this
exact command against a checkout with no prior build artifacts (see
`docs/testing.md`).

To run its test suite:

```bash
pip install -e "src/bindings/python[test]"
pytest tests/python/
```

To run the property-based tests at the larger example count:

```bash
HYPOTHESIS_PROFILE=ci pytest tests/python/test_property.py --hypothesis-show-statistics
```

## 4. Run the MCP server

```bash
pip install -e src/bindings/python
pip install -e src/mcp_server
python src/mcp_server/server.py
```

or, after installing the `mcp_server` package, via its console script:

```bash
citybrain-mcp
```

The server speaks MCP over stdio. To see it work end to end without a full
MCP client, run the bundled demo, which starts the server as a subprocess
and calls every tool once:

```bash
python src/mcp_server/demo.py
```

## Regenerating the golden test vectors

The golden vectors (`tests/vectors/golden.csv`) are generated by an
independent Python script that does **not** import the citybrain package —
it recomputes everything from the mathematical definitions using
arbitrary-precision `Decimal` arithmetic:

```bash
python tests/vectors/gen_vectors.py
```
(run from `brain/`)

Regenerate this only if you are deliberately changing a documented default
or adding new cases; both the C and Python test suites read this file, so
regenerating it changes what both suites check against.

## Clean rebuild

```bash
rm -rf src/build src/bindings/python/_vendor_build src/bindings/python/citybrain/_citybrain_cffi*
```
